# 公众号抓取龙虾

这是放在 `内容生产龙虾/公众号作者文章抓取/` 目录里的自带抓取器副本，供当前 skill 直接调用。实现脚本放在 `./scripts/`，本文件属于 `./references/` 文档层。

本地版微信公众号文章抓取工具。

特点：

- 登录态只保存在本机 `.playwright-profile/`
- 登录失效后固定生成 `login_artifacts/login_qr.png`、`login_artifacts/login_qr.txt`、`login_artifacts/login_status.json`
- `Mac/Linux` 都能用；没有图形界面的环境也可以直接扫字符二维码，或者把 `login_qr.png` 发到 IM 里扫码
- 首次启动会让你选择输出父目录，并设置单次抓取篇数
- 程序会自动在你选中的目录里创建 `输出文章/`
- 每次抓取都会在 `输出文章/` 下面新建一个按公众号名和时间命名的子文件夹
- 每篇文章同时保存 `Markdown` 和原始 `HTML`
- **限流保护**：API 调用与下载均带「固定间隔 + 随机抖动」，遇限流自动指数退避，默认并发降到 3，避免触发公众号封禁
- **去重增强**：输出目录生成 `seen_urls.json` 清单，跨轮 / 跨次自动跳过已抓；失败重试、已下载幂等复用
- **本地时间窗**：`--since/--until` 按中国时区（`Asia/Shanghai`）零点对齐，避免与 UTC 差一天
- **预览模式**：`--dry-run` 只返回将要抓取的清单，不落盘

## Agent 友好 CLI

推荐给 agent / IM / 自动化工具使用这些命令：

```bash
./scripts/run_fetcher.sh ensure-login --json --display silent
./scripts/run_fetcher.sh login-status --json
./scripts/run_fetcher.sh fetch "https://mp.weixin.qq.com/s/你的文章链接" --json --display silent
./scripts/run_fetcher.sh clear-login --json
```

命令说明：

- `ensure-login`
  - 检查并复用现有登录态
  - 如果不能复用，就生成二维码文件并等待扫码成功
- `login-status`
  - 读取当前登录状态文件
  - 适合外层 agent 轮询
- `fetch`
  - 确保登录成功后抓取文章
  - 常用附加参数：`--resume <上一轮articles.json>`（续抓去重）、`--since/--until <YYYY-MM-DD>`（时间窗）、`--dry-run`（仅预览）、`--force-qr`（强制重扫）、`--safe`/`--fast`（限流预设）
- `clear-login`
  - 删除本地登录缓存和二维码产物

典型 JSON 状态：

```json
{
  "status": "authenticated",
  "status_file": "/abs/path/login_status.json",
  "profile_dir": "/abs/path/.playwright-profile",
  "login_artifacts_dir": "/abs/path/login_artifacts"
}
```

```json
{
  "status": "waiting_scan",
  "qr_png_path": "/abs/path/login_qr.png",
  "qr_text_path": "/abs/path/login_qr.txt"
}
```

## 配置

首次运行后会生成 `config.json`，后续要改：

- 输出父目录
- 单次抓取篇数
- 并发数

直接编辑 `config.json` 即可。

无界面 Linux / agent 模式下，如果 `config.json` 不存在，程序会自动生成一份默认模板：

- `output_parent`
  - 当前这份 skill 副本默认使用 skill 根目录本身
  - 也就是 `内容生产龙虾/公众号作者文章抓取/`
- `article_limit`
  - 默认 `20`
- `concurrency`
  - 默认 `3`（已从 6 下调，限流友好；可用 `--safe` 降到 2、`--fast` 拉到 5）
- `display_mode`
  - 无界面环境默认 `silent`
- `tz`
  - 时间窗对齐时区，默认 `Asia/Shanghai`（中国用户）；设 `UTC` 则按世界时零点
- `throttle`
  - 限流参数：`api_min_delay` / `api_max_jitter`（后台 API 间隔与抖动）、`dl_min_delay` / `dl_max_jitter`（下载间隔与抖动）、`max_retries`（单请求重试上限）、`backoff_base`（退避基数，第 n 次重试等待 ≈ `backoff_base × 2^n` 秒）

生成后你直接改 [config.json](/Users/jammy/Desktop/龙虾架构/内容生产龙虾/公众号作者文章抓取/scripts/config.json) 就行，不会要求弹窗配置。

## 二维码登录模式

默认 `display_mode` 是 `auto`，也可以命令行覆盖：

```bash
./scripts/run_fetcher.sh --display auto "https://mp.weixin.qq.com/s/你的文章链接"
./scripts/run_fetcher.sh --display terminal "https://mp.weixin.qq.com/s/你的文章链接"
./scripts/run_fetcher.sh --display image "https://mp.weixin.qq.com/s/你的文章链接"
./scripts/run_fetcher.sh --display silent "https://mp.weixin.qq.com/s/你的文章链接"
```

- `auto`：保存二维码文件；如果当前是终端就打印字符二维码；如果本机有图形界面则尝试打开 PNG
- `terminal`：保存二维码文件，并打印字符二维码
- `image`：保存二维码文件，并优先打开 PNG
- `silent`：只生成二维码文件，不主动展示，适合外层 agent / IM 自己取图发送

## 时间窗（本地时区，已修正）

`--since YYYY-MM-DD` / `--until YYYY-MM-DD` 按发布日期过滤文章：

- 微信文章最新在前，遇到比 `--since` 更老的会**立即停**（后面全是更老的，不浪费请求）。
- `--until` 丢弃比某天更新的（含当天）。
- **默认按中国时区 `Asia/Shanghai`（UTC+8）零点对齐**。微信 `create_time` 是 UTC 秒，工具会换算成"中国当天 0 点"再比较。这修复了旧版按 UTC 零点对齐导致**差一天**的问题（例如 2024-07-08 07:09 的中国文章，旧版误判为旧文，新版正确归为新文）。
- 需要按世界时对齐时加 `--tz UTC`。

```bash
# 只抓近 2 年（2024-07-08 及之后），并跳过已抓
./scripts/run_fetcher.sh fetch "链接" --json --since 2024-07-08 --resume "<上一轮>/articles.json"
# 先预览、不下载
./scripts/run_fetcher.sh fetch "链接" --json --since 2024-07-08 --dry-run
```

## 限流与反封禁

为防止短时间大量请求被腾讯识别为爬虫、触发限流 / 封号，工具在每一层都加了保护：

1. **后台 API 间隔**：每次 `searchbiz` / `appmsgpublish` 调用前插入 `api_min_delay + 随机抖动`（默认 ≈2.0+1.5s）。
2. **下载间隔**：每篇文章下载前插入 `dl_min_delay + 随机抖动`（默认 ≈1.5+1.2s），默认并发 3 路。
3. **自动退避**：遇到 `429` / `5xx` / 接口返回"操作频繁 / 频率"等，按 `backoff_base × 2^n` 指数退避后重试（默认最多 6 次）。
4. **预设切换**：
   - `--safe`：间隔加大、并发降到 2，速度最慢但最稳。
   - `--fast`：间隔减小、并发拉到 5，速度最快但更易触发限流（风险自担）。
   - 也可 `--min-delay` / `--max-jitter` 精细覆盖下载间隔。
5. 以上参数持久化在 `config.json` 的 `throttle` 字段，可长期调。

## 去重与不重复抓取

- **跨轮续抓**：`--resume` 读取上一轮 `articles.json`，只跳过其中 `status=ok` 的文章；**失败的不会进清单，下一轮会被重试**。
- **跨次清单**：每轮在输出目录写 `seen_urls.json`，记录所有已成功下载的归一化链接。即便不传 `--resume`，再次对同目录抓取也会自动跳过已抓文章。
- **幂等复用**：下载前若发现对应 Markdown 已存在且非空，直接复用，不再发请求。
- **归一化**：按 `__biz` / `mid` / `idx` / `sn` 归一化链接，忽略 `chksm` / `scene` 等无关参数与参数顺序，避免同一篇被判成两篇。

## 预览模式（--dry-run）

带 `--dry-run` 时，工具仍会登录并查询文章列表、应用时间窗与去重，但**不下载任何文件**，只返回 `would_download` 清单（标题、链接、发布时间、已抓取标记）。适合"先看看会抓哪些，再决定是否真落盘 / 清理旧文"的工作流。
